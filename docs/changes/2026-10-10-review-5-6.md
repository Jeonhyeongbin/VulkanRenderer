# 리뷰 5·6 — 회전 기즈모와 분리한 변경

## 범위

이 커밋에는 디스크립터 재사용(5번)과 마우스 카메라 코드 정리(6번)만 포함한다. 회전 문제(4번)는 기즈모 및 인스턴스 행렬 변경을 묶은 별도 커밋으로 처리한다. 과거 review-4-5-6 문서의 worldYaw/worldPivot 방식은 최종 회전 구현이 아니다.

## 5번: 디스크립터 할당물 재사용

기존에는 RenderGraph::clear()가 패스를 삭제하면서 패스의 디스크립터 풀/세트도 파괴했다. prepare()가 같은 패스를 다시 구성할 때도 풀과 세트를 재할당했다.

```cpp
// 이전: 매번 할당 (인자 생략)
auto set = DescriptorSet::allocate(...);

// 이후: 캐시에서 가져온 세트가 없을 때만 할당 (인자 생략)
if (!p.readResourcesDescriptorSet)
{
    p.readResourcesDescriptorSet = DescriptorSet::allocate(...);
}
// 세트 내부의 이미지/버퍼 참조는 매번 현재 값으로 갱신
vkUpdateDescriptorSets(device_.handle(), 1, &w, 0, nullptr);
```

호출 흐름은 beginFrame의 현재 슬롯 펜스 대기 → graph.newFrame/clear → 패스 등록 → prepare → render다. clear에서 현재 슬롯의 이전 세트를 descriptorCache_로 이동한다. prepare는 같은 슬롯/패스 순서/이름/pipeline ID에 해당하면 재사용한다. uniform은 uniform 이름도 확인한다. 입력용 세트와 uniform 세트 둘 다 대상이다. reads라는 이름은 CPU에서 세트 내용을 수정하지 않는다는 뜻이 아니다.

RenderGraph.h의 캐시는 패스 선언을 지워도 할당물 수명을 유지하기 위한 보관 장소다. 소유권은 DescriptorSet에 남고 layout 소유권은 Pipeline에 남는다. RenderGraph.cpp는 슬롯별 캐시 이동/복구/정리를, RenderGraphUtil.cpp는 조건부 할당 및 현재 참조 갱신을 담당한다. 새 펜스나 공유 풀 관리자는 추가하지 않았다.

vkUpdateDescriptorSets의 인자는 논리 장치, write 수 1, write 구조체 주소, copy 수 0, copy 없음이다. 반환값은 없고 GPU 완료 대기도 하지 않는다. 슬롯 펜스 대기가 끝난 상태에서 갱신해야 하며 다른 슬롯이 사용 중인 세트는 건드리지 않는다. layout/pipeline 또는 패스 순서가 달라지면 새 할당으로 돌아간다. 리사이즈의 그래프 재생성과 앱 재시작에서도 새로 할당한다. 사용되지 않은 캐시는 다음 clear/그래프 파괴에서 정리한다.

## 6번: 마우스 회전 거리와 각도 제한

Run은 Window::mouseMove() 이후 InputController::move()를 호출한다. 기존 mouseMove의 clamp는 ±80라디안이지만 바로 뒤 move는 ±1라디안이었다. 반환값을 버리는 normalize 호출도 있었다.

```cpp
// 이전 핵심
glm::normalize(deltaPose);
camera.transform.rotation.x = glm::clamp(camera.transform.rotation.x, -80.f, 80.f);

// 이후: normalize 호출 제거, 기존 실제 제한과 일치
camera.transform.rotation.x = glm::clamp(camera.transform.rotation.x, -1.f, 1.f);
```

normalize는 원본을 바꾸지 않고 단위벡터를 반환한다. 결과를 대입하면 마우스 이동 거리 정보가 사라지므로 대입 대신 무효 호출을 제거했다. deltaPose에 기존 감도 0.02를 곱하는 동작은 그대로다. 1라디안은 약 57.3도다. 키보드·Android의 제한값 및 조작 방향은 바꾸지 않았다.

## 검증과 한계

이 변경들이 포함된 작업 트리에서 Windows Debug 빌드 및 Android NDK 문법·타입 검사를 통과했다. 커밋을 나누는 이번 작업은 코드 동작을 추가 변경하지 않는다. 분리한 중간 커밋만 별도 체크아웃해 다시 빌드하지는 않았다.

실제 GPU 동작/Android 기기 실행, 디스크립터 할당 횟수와 프레임 성능 측정은 남아 있다. 내용 write 비용은 그대로이며 성능 검증 완료로 간주하지 않는다. 기존 GraphStructure 테스트는 invalid commandBuffer 호출로 중단된 상태이고 이 커밋에서 테스트 환경을 수정하지 않는다.
